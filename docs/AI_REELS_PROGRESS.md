# AI Reels — журнал разработки и план продолжения

> Состояние на 26 октября 2026 года. Рабочая ветка: `feature/ai-reels`.  
> Документ фиксирует результаты, сообщённые при локальном тестировании в Windows. Он **не означает**, что перечисленные локальные Python-файлы уже загружены в GitHub.

## Цель

Добавить в существующий **iVideoCutter** самостоятельный режим интеллектуального монтажа Reels / Shorts, не ломая обычную нарезку, Telegram watcher, SFTP и загрузчики YouTube/VK.

Планируемый конвейер:

```text
ChatGPT / Codex + SKILL.md
           |
           v
Анализ файла (ffprobe)
           |
           v
Поиск тишины (ffmpeg silencedetect)
           |
           v
Монтажный план (JSON)
           |
           v
Проверка плана и рендер (ffmpeg)
           |
           v
Контроль MP4
```

В последующих этапах: распознавание речи, смысловой монтаж, субтитры по словам, хук/CTA, вставки и музыка. На текущем этапе монтаж основан **только на тишине, а не на понимании речи**.

## Локальная среда

- Windows 10, Python **3.12.10**.
- Отдельная Git worktree-папка для ветки `feature/ai-reels`; рабочая папка `main` сохранена отдельно вместе с незакоммиченными изменениями.
- FFmpeg + FFprobe проверены на обработке видео.
- В локальном `.venv` установлен `openai` SDK **3.38.0**; установка SDK не активирует платный API и не означает передачи данных в облако.
- ChatGPT Plus / Codex рассматриваются как средства работы с проектом; **подписка Plus не включает API-кредиты**.

### Проверка рендерера

Синтетическое видео: 3.000 с, чёрный фон и звук с паузой 1–2 с.

- Планируемый вырезаемый интервал: 1.080–1.920 с.
- Расчётный результат: **2.160 с**.
- Фактический MP4: **2.177007 с**.
- Проверено наличие потоков H.264 (360×640) и AAC.
- Чёрный кадр и гудение **ожидаемы**: они были заложены в тестовый исходник.

### Проверка на настоящем видео

- Длительность исходника: **145.312 с**.
- Детектор нашёл много тихих интервалов; планировщик выбрал **5** удалений.
- Вырезаемые интервалы исходного видео: `7.070–7.613`, `17.252–17.834`, `97.424–98.012`, `135.300–135.938`, `140.571–145.207` с.
- Сохраняемых фрагментов: **6**.
- Расчётная длительность: **138.325 с** (экономия **6.987 с**).
- Полученный MP4 воспроизводился примерно **2 мин 18 с** вместо **2 мин 25 с**.
- Полная проверка декодирования FFmpeg завершилась с кодом **0**.
- При ручном просмотре пользователь сообщил, что качество склеек нормальное.

Это подтверждает **работоспособность базовой нарезки**, но не является автоматической проверкой точности смысловых границ слов.

## Текущие параметры первого прототипа

- `silencedetect`: `noise_level=0.03` (линейная амплитуда, около −30.5 dBFS), `min_duration=0.25` с.
- Защитный отступ от границ паузы: **0.08 с** с каждой стороны.
- Планировщик удаляет фрагменты, если после отступов их длительность не меньше **0.5 с**.
- Скорость в протестированных планах: **1.0×**.
- Оригинал не перезаписывается; рендер создаётся под новым именем.

Параметры пока экспериментальные; их нельзя считать универсальными для любой записи.

## Что ещё НЕ реализовано

- Распознавание речи и временные отметки каждого слова.
- Осмысленное удаление «ээ», повторов и неудачных дублей.
- Пословные субтитры и выравнивание по новой временной шкале.
- Ускорение речи, нормализация громкости и кроссфейды звука.
- Хук, CTA, вставки, динамический зум, музыка и фирменная графика.
- Вкладка AI Reels в PyQt, автоматизированные регрессионные тесты и непрерывная интеграция.
- Подтверждённая загрузка **локальных** модулей `ai_reels/`, `AGENTS.md` и `SKILL.md` в удалённую ветку.

## Открытый выбор перед следующим этапом

**Распознавание речи:**

1. **Локально без платы за API** — `faster-whisper` / whisper.cpp на CPU либо при наличии совместимой GPU-среды Windows.
2. **Облачный OpenAI API** — отдельная биллинговая настройка и согласие на передачу видео/аудио.

**Решение пока не принято.** Сначала обсудить с пользователем, затем выбрать один способ. Ни API-ключи, ни локальные модели пока настраивать не требуется.

## Следующие действия (по одному шагу)

1. Выбрать способ распознавания речи; при локальном варианте начать с проверки совместимости и короткого теста на CPU.
2. Разработать `transcriber.py` с единым интерфейсом распознавания независимо от провайдера.
3. Объединить пословные таймкоды с картой вырезанных интервалов.
4. Генерировать и проверять субтитры (ASS/SRT), затем прожигать их в тестовом MP4.
5. После стабильных тестов добавить шаблон оформления и отдельный режим в GUI.
