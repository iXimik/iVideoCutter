# Безопасность репозитория

## Что никогда не коммитить

- `config/settings.json`, `config/telegram_settings.json`, `config/youtube_settings.json`, `config/vk_settings.json`.
- `credentials/client_secret.json`, `credentials/youtube_token.json`, любые OAuth-ключи и refresh token.
- `telegram_sessions/`, `*.session` — Telethon хранит здесь авторизацию.
- `input/`, `output/`, `logs/`, историю публикаций, дампы, локальную базу очереди.
- Личные аккаунты, адреса, идентификаторы групп и пути пользователя в примерах.

## Перед публикацией

1. Используйте `git status --ignored`; убедитесь, что секреты игнорируются.
2. Проверяйте staged-файлы: `git diff --cached --name-only`.
3. Ищите чувствительные данные: `git grep -n -i -E "access_token|api_hash|client_secret|refresh_token|password"` и вручную анализируйте найденные строки. Совпадения в **названиях переменных** нормальны.
4. Настройте secret scanning / push protection в GitHub, если доступны.
5. Если токен попал в публичный коммит — **отзовите токен**, замените его и удалите его из Git-истории специальной процедурой. Простой `git rm` не удаляет его из старых коммитов.

## Примеры настроек

Коммитьте только файлы `*.example.json` с пустыми значениями. Для рабочего приложения скопируйте их в `*.json` и редактируйте локально. Пустой `access_token` означает, что VK-загрузка не готова, это ожидаемо.

## Публичность

Репозиторий открыт. Считайте любой опубликованный файл общедоступным.
